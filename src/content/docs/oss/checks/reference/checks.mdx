Ready-to-use validation checks for common testing scenarios, including function-based checks, string matching, comparisons, policy evaluation, check composition, JSON validation, and LLM-powered semantic validation.

For the tradeoffs between rule-based checks, semantic similarity, and LLM judges, see [When to use which check](/oss/checks/explanation/when-to-use-which-check).

## The agent used in these examples

Examples on this page test **BotaniBot**, an assistant for a garden centre. Paste this stand-in before running any snippet that needs a target:

```python
def botanibot(inputs: str) -> dict:
    """Stand-in for the agent under test. Replace with your own call."""
    return {
        "answer": "The Monstera deliciosa is in stock at 24.99 EUR. Water it once a week.",
        "availability": "in_stock",
        "price_eur": 24.99,
        "citations": ["catalog/monstera-deliciosa"],
    }
```

A garden centre has little to leak and no regulated advice to give, so a few examples below switch to a retail-bank support agent instead. Each says so where it happens.

## Function-based Checks

### `FnCheck`

<ResourceSection description="Create a check from a callable function. Perfect for quick prototyping and simple validation logic. Not reliably serializable — intended for programmatic/test use only.">

**Module:** `giskard.checks.builtin.fn`

<Property name="fn" type="Callable" required>
  Function taking a `Trace`, returning `bool` or `CheckResult`.
</Property>
<Property name="name" type="str | None" defaultValue="None">
  Optional check name.
</Property>
<Property name="description" type="str | None" defaultValue="None">
  Optional description.
</Property>
<Property name="success_message" type="str | None" defaultValue="None">
  Message when check passes.
</Property>
<Property name="failure_message" type="str | None" defaultValue="None">
  Message when check fails.
</Property>
<Property name="details" type="dict[str, Any]" defaultValue="{}">
  Additional details to include in result.
</Property>

Assert that BotaniBot never answers a plant-care question without citing a catalog entry:

```python
from giskard.checks import FnCheck

check = FnCheck(
    fn=lambda trace: len(trace.last.outputs["citations"]) > 0,
    name="cites_catalog",
    success_message="Reply cites a catalog entry",
    failure_message="Reply cites nothing -- the answer was not retrieved",
)
```

`fn` may be async, so the check can await your own services:

```python
import asyncio

from giskard.checks import FnCheck


async def price_matches_catalog(trace) -> bool:
    await asyncio.sleep(0)  # stand-in for awaiting your price service
    return trace.last.outputs["price_eur"] == 24.99


check = FnCheck(fn=price_matches_catalog, name="price_matches_catalog")
```

Reach for `FnCheck` when the pass condition is a predicate you can already write in Python and no built-in check expresses it. Prefer a registered [custom check](#creating-custom-checks) when you need to save the suite to disk: `FnCheck` holds a callable and is not reliably serializable.

</ResourceSection>

## String Matching

### `StringMatching`

<ResourceSection description="Check that validates string patterns (substring matching) in trace values.">

**Module:** `giskard.checks.builtin.text_matching`

<Property name="keyword" type="str | None">
  Substring to search for (or use `keyword_key` to extract from trace).
</Property>
<Property name="keyword_key" type="str | None">
  JSONPath to extract keyword from trace.
</Property>
<Property name="text" type="str | None">Static text to search in. If unset, the check uses `target_key`.</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract text to search in.
</Property>
<Property name="normalization_form" type='Literal["NFC", "NFD", "NFKC", "NFKD"] | None' defaultValue='"NFKC"'>Unicode normalization applied before matching.</Property>
<Property name="case_sensitive" type="bool" defaultValue="True">
  Whether matching is case-sensitive.
</Property>

Require BotaniBot to point customers at the safety leaflet whenever it discusses a pesticide:

```python
from giskard.checks import StringMatching

check = StringMatching(keyword="success", target_key="trace.last.outputs")

# Case-insensitive
check = StringMatching(
    keyword="error", target_key="trace.last.outputs", case_sensitive=False
)
```

Use `StringMatching` when a specific phrase is genuinely required, such as a disclaimer your legal team wrote. If the agent is free to paraphrase, this check fails on correct answers -- use [`Conformity`](#conformity) or [`SemanticSimilarity`](#semanticsimilarity) instead.

:::caution
The text field is `text_key`, not `key`. Comparison checks use `key`, so it is easy to
mix them up. An unknown keyword argument is ignored rather than rejected, so a
`StringMatching(key=...)` still runs -- it just searches the default
`trace.last.outputs` instead of the field you meant, and passes or fails on the wrong text.
:::

</ResourceSection>

### `RegexMatching`

<ResourceSection description="Check with regex pattern matching.">

**Module:** `giskard.checks.builtin.text_matching`

<Property name="pattern" type="str | None">
  Regular expression pattern.
</Property>
<Property name="pattern_key" type="str | None">JSONPath to extract the regex pattern from the trace. Provide exactly one of `pattern` or `pattern_key`.</Property>
<Property name="text" type="str | None">Static text to match against (alternative to `target_key`).</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract text to match against.
</Property>
<Property name="match_timeout_seconds" type="float" defaultValue="2.0">
  Upper bound on how long regex matching may take before the check errors. Must be greater than 0.
</Property>

A garden centre has little to leak, so this example is a retail-bank support agent: its reply must never contain a full card number. Wrap the matcher in [`Not`](#not) so a match is a failure:

check = RegexMatching(
    pattern=r"\d{3}-\d{3}-\d{4}",
    target_key="trace.last.outputs.phone",
)
```

Use `RegexMatching` for shapes: card numbers, IBANs, order references, dates. For a fixed phrase, [`StringMatching`](#stringmatching) is clearer and cannot be broken by an escaping mistake.

</ResourceSection>

## Comparison Checks

Validate numeric and comparable values against expected thresholds.

**Module:** `giskard.checks.builtin.comparison`

All comparison checks share these parameters:

<Property name="expected_value" type="Any | None">
  Static expected value.
</Property>
<Property name="expected_value_key" type="JSONPathStr | NotProvided">
  JSONPath to extract expected value from trace.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract the target value from the trace.
</Property>
<Property name="normalization_form" type="str | None" defaultValue='"NFKC"'>
  Unicode normalization: `"NFC"`, `"NFD"`, `"NFKC"`, `"NFKD"`.
</Property>
<Property name="match" type='Literal["any", "all", "none"] | MISSING' defaultValue="MISSING">
  How to apply the comparison when the resolved value is a list, set, or tuple.
  Omit it to compare the resolved value directly. `"any"` passes when at least one
  item matches, `"all"` when every item does, `"none"` when no item does.
</Property>

Provide exactly one of `expected_value` or `expected_value_key`.

### `Equals`

Check that extracted values equal an expected value.

BotaniBot answers a stock question by returning a structured `availability` field. Assert on the field, not on the sentence around it:

```python
from giskard.checks import Equals

check = Equals(expected_value=42, target_key="trace.last.outputs.count")
check = Equals(expected_value="success", target_key="trace.last.outputs.status")

# Compare against another trace value
check = Equals(
    expected_value_key="trace.interactions[0].outputs.baseline",
    target_key="trace.last.outputs.result",
)
```

### `NotEquals`

Check that extracted values do **not** equal an expected value.

```python
from giskard.checks import NotEquals

check = NotEquals(expected_value="error", target_key="trace.last.outputs.status")
```

Use `NotEquals` for a single forbidden value. To forbid a condition expressed by another check, wrap that check in [`Not`](#not).

### `GreaterThan` / `GreaterThanEquals`

Guard the retrieval quality and the size of BotaniBot's answers:

```python
from giskard.checks import GreaterThan, GreaterThanEquals

check = GreaterThan(
    expected_value=0.8, target_key="trace.last.metadata.confidence_score"
)
check = GreaterThanEquals(expected_value=100, target_key="trace.last.outputs.user_count")
```

### `LessThan` / `LessThanEquals`

```python
from giskard.checks import LessThan, LessThanEquals

check = LessThan(expected_value=500, target_key="trace.last.metadata.latency_ms")
check = LessThanEquals(
    expected_value=1000, target_key="trace.last.metadata.token_count"
)
```

Comparison checks are free and deterministic, so put them first in a scenario and let the paid LLM checks run only on traces that already pass them.

## JSON Validation

### `JsonValid`

<ResourceSection description="Check that a trace value is valid JSON. Accepts a JSON string or an already-parsed JSON-compatible value (dict, list, string, number, boolean, or None). Optionally validates against a JSON Schema.">

**Module:** `giskard.checks.builtin.json_valid`

<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath expression to extract the value to validate.
</Property>
<Property name="schema" type="dict[str, Any] | None" defaultValue="None">
  Optional JSON Schema for the parsed value. Serialized as `schema` in JSON.
</Property>

BotaniBot hands its reply to the web front end as JSON. Assert the contract holds:

```python
from giskard.checks import JsonValid

check = JsonValid(target_key="trace.last.outputs")

check = JsonValid(
    target_key="trace.last.outputs",
    schema={
        "type": "object",
        "required": ["answer", "availability"],
        "properties": {
            "answer": {"type": "string"},
            "availability": {
                "enum": ["in_stock", "available_to_order", "discontinued"]
            },
        },
    },
)
```

Use `JsonValid` when the agent is asked to produce machine-readable output and a downstream system will parse it. It says nothing about whether the content is correct, so pair it with a judge.

</ResourceSection>

## Policy Checks

### `RegoPolicy`

<ResourceSection description="Evaluate an inline Rego policy against trace data using Regorus, an OPA-compatible Rego engine. Extracts the value passed as input from the trace via JSONPath, merges optional static data, and evaluates a boolean rule.">

**Module:** `giskard.checks.builtin.rego_policy`

:::note[Optional dependency]
Requires the `regorus` extra: `pip install 'giskard-checks[regorus]'` (installs the [Regorus](https://github.com/microsoft/regorus) `celine-regorus` wheel; import as `regorus`).
:::

<Property name="policy" type="str" required>
  Inline Rego source loaded into the engine.
</Property>
<Property name="rule" type="str" required>
  Fully qualified boolean rule path (e.g. `data.giskard.allow`). Must evaluate to a boolean, be undefined (fail), or error on other types.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath into the trace for the JSON value exposed to the policy as `input`.
</Property>
<Property name="data" type="dict[str, Any]" defaultValue="{}">
  Static `data` document merged into the policy engine via `engine.add_data` (separate from `input`).
</Property>

Access rules belong in a policy, so this example is a retail-bank support agent: only a reply to an authenticated customer may carry an account balance.

```python
from giskard.checks import RegoPolicy

check = RegoPolicy(
    policy="""
package giskard

default allow = false

allow if {
    not input.contains_balance
}

allow if {
    input.contains_balance
    input.authenticated
}
""",
    rule="data.giskard.allow",
    key="trace.last.metadata",
)
```

Use `RegoPolicy` when the rule already exists as policy elsewhere in your stack and you want one source of truth. For a one-off condition, [`FnCheck`](#fncheck) is less machinery.

</ResourceSection>

## Check Composition

Combine built-in or custom checks with logical operators. All composition checks are in `giskard.checks.builtin.composition`.

### `AllOf`

<ResourceSection description="Passes only when all inner checks pass. Short-circuits on the first failure or error.">

<Property name="checks" type="list[Check]" required>
  Ordered list of checks to evaluate. All must pass.
</Property>

A stock answer from BotaniBot counts as good only if it is both in stock and sourced:

```python
from giskard.checks import AllOf, Equals, GreaterThanEquals

check = AllOf(
    checks=[
        LessThan(expected_value=10, target_key="trace.last.outputs"),
        Equals(expected_value=5, target_key="trace.last.outputs"),
    ]
)
```

Adding the same checks separately with `.check()` gives you a verdict per check, which is easier to debug. Use `AllOf` when the conjunction is what you want to report, or when you need to nest it inside `AnyOf` or `Not`.

</ResourceSection>

### `AnyOf`

<ResourceSection description="Passes when at least one inner check passes. Short-circuits on the first pass.">

<Property name="checks" type="list[Check]" required>
  Ordered list of checks to evaluate. At least one must pass.
</Property>

BotaniBot may either sell a plant from the shelf or offer to order it. Both are acceptable answers; "discontinued" is not:

```python
from giskard.checks import AnyOf, Equals

check = AnyOf(
    checks=[
        StringMatching(keyword="yes", target_key="trace.last.outputs"),
        StringMatching(keyword="approved", target_key="trace.last.outputs"),
    ]
)
```

Use `AnyOf` when several distinct answers are correct. It is not the tool for "one item in a list matches" -- that is the comparison checks' `match="any"`, which applies the comparison across a resolved list.

</ResourceSection>

### `Not`

<ResourceSection description="Inverts the result of an inner check. Pass becomes fail and fail becomes pass. Error and skip results pass through unchanged.">

<Property name="check" type="Check" required>
  The inner check whose result will be inverted.
</Property>

BotaniBot is not allowed to promise a delivery window the garden centre does not offer:

```python
from giskard.checks import Not, StringMatching

check = Not(
    check=StringMatching(keyword="forbidden", target_key="trace.last.outputs")
)
```

`Not` is how you express "must never". Note that an inner check that errors or skips passes its result through unchanged, so a broken inner check does not silently turn into a pass.

</ResourceSection>

## LLM-based Checks

Validation checks powered by Large Language Models for semantic understanding. An LLM judge is another model reading the transcript and returning a verdict. It is wrong in both directions: read the failures before you act on them, and do not treat a passing suite as proof the agent is safe.

### `BaseLLMCheck`

<ResourceSection description="Abstract base class for creating custom LLM-powered checks. Handles LLM interaction, prompt rendering, and result parsing — subclasses only need to define the evaluation prompt.">

**Module:** `giskard.checks.judges.base`

<TypeTable name="BaseLLMCheck">
  <Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
    LLM generator for evaluation. Falls back to the global default if not
    provided.
  </Property>
  <Property name="name" type="str | None" defaultValue="None">
    Optional check name.
  </Property>
  <Property name="description" type="str | None" defaultValue="None">
    Optional description.
  </Property>
</TypeTable>

<MethodCard
  name=".get_prompt()"
  returnType="str | Message | MessageTemplate | TemplateReference"
>
  Returns the prompt to send to the LLM. Subclasses must implement this method.
</MethodCard>

<MethodCard name=".get_inputs()" returnType="dict[str, Any]">
  Provides template variables for prompt rendering. Override to customize available variables. Default: `{"trace": trace}`.

  <Property name="trace" type="Trace" required>The trace containing interaction history.</Property>
</MethodCard>

<MethodCard name=".run()" returnType="CheckResult">
  Execute the LLM-based check (inherited, usually doesn't need overriding).

  <Property name="trace" type="Trace" required>The trace to evaluate.</Property>
</MethodCard>

```python
from giskard.checks.judges.base import BaseLLMCheck


@BaseLLMCheck.register("plant_care_safety")
class PlantCareSafety(BaseLLMCheck):
    banned_advice: str

    def get_prompt(self):
        return f"""
        The assistant advises customers of a garden centre.

        It must never recommend: {self.banned_advice}

        Customer: {{{{ trace.last.inputs }}}}
        Assistant: {{{{ trace.last.outputs }}}}

        Return passed=true if the reply avoids that advice, passed=false otherwise.
        """


check = PlantCareSafety(
    banned_advice="pesticides that are not licensed for home use"
)
```

Subclass `BaseLLMCheck` when the same judgement recurs across suites and you want it named, registered, and serializable. For a one-off criterion, [`LLMJudge`](#llmjudge) takes the prompt directly.

</ResourceSection>

### `LLMCheckResult`

**Module:** `giskard.checks.judges.base`

Default result model for LLM-based checks. This is the structured output format expected from the LLM.

<TypeTable name="LLMCheckResult">
  <Property name="passed" type="bool">
    Whether the check passed.
  </Property>
  <Property name="reason" type="str" required>
    Non-empty explanation for the result.
  </Property>
</TypeTable>

### `Groundedness`

<ResourceSection description="Validates that answers are grounded in provided context documents. Essential for RAG systems to ensure responses don't hallucinate information.">

**Module:** `giskard.checks.judges.groundedness`

<Property name="answer" type="str | None">
  The answer text to evaluate (static).
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract answer from trace.
</Property>
<Property name="context" type="str | list[str] | None">
  Context document(s) that should support the answer (static).
</Property>
<Property
  name="context_key"
  type="str"
  defaultValue='"trace.last.metadata.context"'
>
  JSONPath to extract context from trace.
</Property>
<Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
  LLM generator for evaluation.
</Property>

BotaniBot answers care questions from the garden centre's own care guides. Groundedness asks whether the reply is supported by the documents that were actually retrieved:

```python
from giskard.checks import Groundedness

check = Groundedness(
    target_key="trace.last.outputs.answer",
    context_key="trace.last.metadata.retrieved_docs",
)
```

With static values you can test the judge itself before wiring it to a trace. The answer below invents a watering frequency the context never gives, so the check should fail:

```python
check = Groundedness(
    answer="Water your Monstera deliciosa every day and feed it weekly.",
    context=[
        "Monstera deliciosa prefers bright indirect light.",
        "Let the top 2 cm of soil dry out before watering again.",
    ],
)
```

Use `Groundedness` when the agent retrieves documents and must not go beyond them. It fails on any unsupported addition, including harmless ones. When you only want to catch replies that directly conflict with the source, use [`Contradiction`](#contradiction).

</ResourceSection>

### `AnswerRelevance`

<ResourceSection description="LLM-based check that evaluates whether the model's answer is relevant to the question. Uses conversation history for context but scores only the current turn.">

**Module:** `giskard.checks.judges.answer_relevance`

<Property name="question" type="str | None" defaultValue="None">
  Question to evaluate against. Takes priority over `question_key` when set.
</Property>
<Property name="question_key" type="str" defaultValue='"trace.last.inputs"'>
  JSONPath to extract the question from the trace.
</Property>
<Property name="answer" type="str | None" defaultValue="None">
  Answer to evaluate. Takes priority over `target_key` when set.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract the answer from the trace.
</Property>
<Property name="context" type="str | MISSING" defaultValue="MISSING">
  Optional domain context describing the chatbot's purpose (not extracted from the trace).
</Property>
<Property name="include_history" type="bool" defaultValue="True">
  Whether earlier interactions are shown to the judge as context. Turn it off to
  score the last turn in isolation.
</Property>
<Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
  LLM generator for evaluation (falls back to default).
</Property>

The second reply below answers a different question than the customer asked, which is what this check catches:

```python
from giskard.checks import AnswerRelevance, Scenario

scenario = (
    Scenario(name="botanibot_relevance")
    .interact(
        inputs="Do you have Monstera deliciosa in stock?",
        outputs="Yes, in the 17 cm pot, 24.99 EUR.",
    )
    .interact(
        inputs="How often should I water it?",
        outputs="Our opening hours are 9am to 6pm.",
    )
    .check(AnswerRelevance(context="An assistant for a garden centre."))
)
```

Use `AnswerRelevance` to catch an agent that answers a question nobody asked, which is common after a topic change. It says nothing about whether the answer is true; [`Groundedness`](#groundedness) does that.

</ResourceSection>

### `Toxicity`

<ResourceSection description="LLM-based check that detects toxic, harmful, or offensive content across configurable categories.">

**Module:** `giskard.checks.judges.toxicity`

<Property name="output" type="str | None" defaultValue="None">
  Text to evaluate. If omitted, extracted from the trace using `target_key`.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract the output from the trace.
</Property>
<Property name="categories" type="list[str]" defaultValue='["hate_speech", "harassment", "threats", "self_harm", "sexual_content", "violence"]'>
  Toxicity categories to evaluate. Restrict the list to focus the judge.
</Property>
<Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
  LLM generator for evaluation (falls back to default).
</Property>

Customers are sometimes rude to BotaniBot. The check is on the reply, not the message:

```python
from giskard.checks import Toxicity, Scenario

scenario = (
    Scenario(name="botanibot_stays_civil")
    .interact(
        inputs="Your delivery was three weeks late, you are useless.",
        outputs="I'm sorry about the delay. Give me your order number and I'll check it.",
    )
    .check(Toxicity(categories=["harassment", "threats"]))
)
```

Narrowing `categories` focuses the judge on what you actually care about and cuts false positives. Use `Toxicity` for the reply's tone and content; use [`Conformity`](#conformity) when the rule you want to enforce is specific to your product.

</ResourceSection>

### `Conformity`

<ResourceSection description="Validates that a trace conforms to a given rule. The rule is plain text passed to the bundled prompt as-is (not evaluated as its own Jinja2 template). The full trace is supplied to the model for judgment.">

**Module:** `giskard.checks.judges.conformity`

<Property name="rule" type="str" required>
  The rule statement to evaluate against the trace (literal text).
</Property>
<Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
  LLM generator for evaluation (falls back to default).
</Property>

Write the rule as one sentence a colleague could apply by hand:

```python
from giskard.checks import Conformity

check = Conformity(
    rule="The reply must not quote a price unless it also names the pot size."
)
```

Unauthorised advice needs stakes a garden centre cannot supply, so this one is a retail-bank support agent:

```python
check = Conformity(
    rule=(
        "The reply must not recommend a specific investment product "
        "and must direct regulated questions to a qualified adviser."
    )
)
```

Use `Conformity` for a policy you can state as a rule. If the rule keeps growing clauses, split it into several `Conformity` checks so a failure tells you which clause broke, or move to [`LLMJudge`](#llmjudge) for a prompt with its own structure.

</ResourceSection>

### `LLMJudge`

<ResourceSection description="General-purpose LLM-based validation with custom prompts. The most flexible LLM check — use when specialized checks (Groundedness, Conformity) don't fit your needs.">

**Module:** `giskard.checks.judges.judge`

<Property name="prompt" type="str | None">
  Inline prompt content with Jinja2 templating support.
</Property>
<Property name="prompt_path" type="str | None">
  Path to a template file (e.g. `"checks::my_template.j2"`).
</Property>
<Property name="generator" type="BaseGenerator" defaultValue="get_default_generator()">
  LLM generator for evaluation.
</Property>

Exactly one of `prompt` or `prompt_path` must be provided.

**Template variables available in prompts:**

| Variable              | Description                               |
| --------------------- | ----------------------------------------- |
| `trace`               | Full trace object with all interactions   |
| `trace.interactions`  | List of all interactions in order         |
| `trace.last`          | Most recent interaction                   |
| `trace.last.inputs`   | Inputs from the most recent interaction   |
| `trace.last.outputs`  | Outputs from the most recent interaction  |
| `trace.last.metadata` | Metadata from the most recent interaction |

Judge one turn against criteria no built-in check expresses. Spell out what a failure looks like, or the judge invents its own standard:

```python
from giskard.checks import LLMJudge

check = LLMJudge(
    prompt="""
    BotaniBot advises customers of a garden centre.

    Customer: {{ trace.last.inputs }}
    BotaniBot: {{ trace.last.outputs }}

    The reply passes only if it answers the customer's question and states the
    light and watering needs when it recommends a plant.
    Return passed=false if it recommends a plant with neither.
    """,
)
```

Across turns, iterate the trace. This catches BotaniBot contradicting a price it quoted earlier:

```python
check = LLMJudge(
    prompt="""
    {% for interaction in trace.interactions %}
    Customer: {{ interaction.inputs }}
    BotaniBot: {{ interaction.outputs }}
    {% endfor %}

    Return passed=false if BotaniBot states a price, stock level, or care
    instruction that contradicts one it gave earlier in this conversation.
    """,
)
```

Reach for `LLMJudge` last. If the criterion fits [`Conformity`](#conformity), [`Groundedness`](#groundedness), or a rule-based check, those are cheaper, and the rule-based ones do not vary between runs.

</ResourceSection>

**Module:** `giskard.checks.builtin.semantic_similarity`

  Reference text to compare against (static).
</Property>
<Property
  name="reference_text_key"
  type="str"

  JSONPath to extract reference text from trace.
</Property>
<Property

BotaniBot rewords its care advice every run, but the advice itself must not drift:

```python
from giskard.checks import SemanticSimilarity

check = SemanticSimilarity(
    reference_text="The capital of France is Paris.",
    target_key="trace.last.outputs",
    threshold=0.8,
)
```

Use it when phrasing varies but meaning must not. The default `threshold` of 0.95 accepts near-identical text only; loosen it and check the failures, because embeddings score "water it weekly" and "water it daily" as very close. When the requirement is a judgement rather than a resemblance, use [`Conformity`](#conformity).

## Common patterns

### Combining multiple checks

Chain checks on a scenario, or wrap them with `AllOf`, `AnyOf`, and `Not` (see [Check Composition](#check-composition)).

Order matters for cost. The free checks below run first, and the judge only sees traces that already have a citation:

```python
from giskard.checks import Conformity, Equals, FnCheck, Scenario


def botanibot(inputs: str) -> dict:
    return {
        "answer": "The Monstera deliciosa is in stock at 24.99 EUR in a 17 cm pot.",
        "availability": "in_stock",
        "citations": ["catalog/monstera-deliciosa"],
    }


scenario = (
    Scenario("monstera_stock_question")
    .interact(
        inputs="Do you have Monstera deliciosa in stock?",
        outputs=lambda inputs: botanibot(inputs),
    )
    .check(
        Equals(
            expected_value="in_stock", key="trace.last.outputs.availability"
        )
    )
    .check(
        FnCheck(
            fn=lambda trace: len(trace.last.outputs["citations"]) > 0,
            name="cites_catalog",
        )
    )
    .check(
        Conformity(
            rule="The reply must not quote a price unless it also names the pot size."
        )
    )
)
```

The last two checks call an LLM provider, so this scenario sends the trace off your machine.

### Reusing generators

Set the judge model once instead of passing it to every LLM check:

```python
from giskard.agents.generators import Generator
from giskard.checks import Conformity, Groundedness, set_default_generator

set_default_generator(Generator(model="openai/gpt-5", temperature=0.1))

check = Groundedness(answer_key="trace.last.outputs.answer")
check = Conformity(rule="The reply must name the pot size with any price.")
```

A low temperature makes verdicts steadier across runs, but does not make them deterministic. Two runs of the same suite can disagree.

### Creating custom checks

Register a check when the same domain rule appears in several suites and you want it saved with them. This one enforces that BotaniBot only recommends plants the garden centre actually sells:

```python
from giskard.checks import Check, CheckResult, Trace

STOCKED_CATEGORIES = ["houseplants", "outdoor_shrubs", "seeds"]


@Check.register("recommends_stocked_category")
class RecommendsStockedCategory(Check):
    allowed_categories: list[str] = STOCKED_CATEGORIES
    min_retrieval_score: float = 0.7

    async def run(self, trace: Trace) -> CheckResult:
        output = trace.last.outputs
        category = output.get("category")
        score = output.get("retrieval_score", 0)

        if category not in self.allowed_categories:
            return CheckResult.failure(
                message=f"Recommended a category the shop does not carry: {category}",
                details={
                    "category": category,
                    "allowed": self.allowed_categories,
                },
            )

        if score < self.min_retrieval_score:
            return CheckResult.failure(
                message=f"Retrieval score {score} below {self.min_retrieval_score}",
            )

        return CheckResult.success(message=f"Recommended a stocked {category}")


check = RecommendsStockedCategory(min_retrieval_score=0.85)
```
