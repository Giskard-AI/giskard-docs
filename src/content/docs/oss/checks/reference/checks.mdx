Ready-to-use validation checks: function-based checks, string and regex matching, comparisons, policy evaluation, composition, JSON validation, and LLM judges.

For the tradeoffs between rule-based checks, semantic similarity, and LLM judges, see [When to use which check](/oss/checks/explanation/when-to-use-which-check).

## `MISSING` and `None`

Most checks accept a value in two ways: as a static field (`keyword`, `expected_value`, `answer`, `context`, …) or as a JSONPath into the trace (`keyword_key`, `expected_value_key`, `target_key`, `context_key`, …). Those static fields default to `MISSING`, the sentinel from `pydantic.experimental.missing_sentinel`, and not to `None`:

```python
from pydantic.experimental.missing_sentinel import MISSING
```

`MISSING` means *you did not supply a value*, so the check falls back to the matching `*_key` path. Passing `None` explicitly supplies `None` **as the value** and the fallback does not happen — a static `None` is compared, matched, or judged like any other value. This is the most common source of a check that quietly evaluates the wrong thing, so leave the field out rather than passing `None` to mean "unset".

You rarely need to import `MISSING` yourself. It appears in this page's default columns to show which fields behave this way.

:::caution[Unknown keyword arguments are rejected]
Every `Check` sets `extra="forbid"`, so a misspelled field name raises `ValidationError: … extra_forbidden` instead of being silently dropped. `Scenario` deliberately does the opposite and tolerates unknown keys — see [Errors](/oss/checks/reference/core#errors) for why.
:::

## Function-based Checks

### `FnCheck`

<ResourceSection description="Create a check from a callable function. Use it for quick prototyping and one-off validation logic. Not reliably serializable — intended for programmatic/test use only.">

**Module:** `giskard.checks.builtin.fn`

<Property name="fn" type="Callable" required>
  Function taking a `Trace`, returning `bool` or `CheckResult`.
</Property>
<Property name="name" type="str | None" defaultValue="None">
  Optional check name.
</Property>
<Property name="description" type="str | None" defaultValue="None">
  Optional description.
</Property>
<Property name="success_message" type="str | None" defaultValue="None">
  Message when check passes.
</Property>
<Property name="failure_message" type="str | None" defaultValue="None">
  Message when check fails.
</Property>
<Property name="details" type="dict[str, Any]" defaultValue="{}">
  Additional details to include in result.
</Property>

Assert that the agent never quotes a fee without citing the source it came from:

```python
from giskard.checks import FnCheck

check = FnCheck(
    fn=lambda trace: trace.last is not None
    and len(trace.last.outputs["citations"]) > 0,
    name="cites_fee_schedule",
    success_message="Reply cites a source document",
    failure_message="Reply cites nothing, so the figure was not retrieved",
)
```

`fn` may be async, so the check can await your own services:

```python
import asyncio

from giskard.checks import FnCheck


async def fee_matches_schedule(trace) -> bool:
    await asyncio.sleep(0)  # stand-in for awaiting your fee-schedule service
    return "3.00 EUR" in trace.last.outputs["answer"]


check = FnCheck(fn=fee_matches_schedule, name="fee_matches_schedule")
```

Reach for `FnCheck` when the pass condition is a predicate you can already write in Python and no built-in check expresses it. Prefer a registered [custom check](/oss/checks/how-to/custom-checks) when you need to save the suite to disk: `fn` is declared `Field(exclude=True)`, so it is dropped from `model_dump()` and a round-tripped `FnCheck` has no function to run.

**Raises:** `TypeError` from `.run()` when `fn` returns anything other than a `bool` or a `CheckResult` (or an awaitable of one) — the message is `from_fn callable must return bool or CheckResult (or awaitable thereof), but got …`.

</ResourceSection>

### `from_fn`

<ResourceSection description="Factory that builds an FnCheck from a callable. Same behaviour, less punctuation.">

**Module:** `giskard.checks.builtin.fn`

<MethodCard name="from_fn()" returnType="Check">
  Helper form of `FnCheck`: build one from a callable. Exported from `giskard.checks`. Every option other than `fn` is keyword-only.

  <Property name="fn" type="Callable" required>Function taking a `Trace` and returning `bool` or `CheckResult`, sync or async.</Property>
  <Property name="name" type="str | None" defaultValue="None">Optional check name.</Property>
  <Property name="description" type="str | None" defaultValue="None">Optional description.</Property>
  <Property name="success_message" type="str | None" defaultValue="None">Message when the check passes.</Property>
  <Property name="failure_message" type="str | None" defaultValue="None">Message when the check fails.</Property>
  <Property name="details" type="dict[str, Any] | None" defaultValue="None">Details attached to the result. `None` becomes `{}`.</Property>
</MethodCard>

```python
from giskard.checks import from_fn

    lambda trace: trace.last is not None and bool(trace.last.outputs),
    name="has_output",
)
```

`from_fn` returns an `FnCheck` — it is the same check, built for you — so the serialization caveat above applies to it too.

</ResourceSection>

## String Matching

### `StringMatching`

<ResourceSection description="Check that validates string patterns (substring matching) in trace values.">

**Module:** `giskard.checks.builtin.text_matching`

<Property name="keyword" type="str | MISSING" defaultValue="MISSING">
  Substring to search for. Left at `MISSING`, the check reads `keyword_key`.
</Property>
<Property name="keyword_key" type="JSONPathStr | MISSING" defaultValue="MISSING">
  JSONPath to extract the keyword from the trace.
</Property>
<Property name="text" type="str | MISSING" defaultValue="MISSING">Static text to search in. Left at `MISSING`, the check reads `target_key`.</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract text to search in.
</Property>
<Property name="normalization_form" type='Literal["NFC", "NFD", "NFKC", "NFKD"] | None' defaultValue='"NFKC"'>Unicode normalization applied before matching.</Property>
<Property name="case_sensitive" type="bool" defaultValue="True">
  Whether matching is case-sensitive.
</Property>

Require an exact phrase, such as a disclaimer your legal team signed off on:

```python
from giskard.checks import StringMatching

status_is_success = StringMatching(
    keyword="success", target_key="trace.last.outputs"
)

# Case-insensitive
carries_disclaimer = StringMatching(
    keyword="this is not financial advice",
    target_key="trace.last.outputs.answer",
    case_sensitive=False,
)
```

Use `StringMatching` when a specific phrase is required, such as a disclaimer your legal team wrote. If the agent is free to paraphrase, this check fails on correct answers; use [`Conformity`](#conformity) or [`SemanticSimilarity`](#semanticsimilarity) instead.

</ResourceSection>

### `RegexMatching`

<ResourceSection description="Check with regex pattern matching.">

**Module:** `giskard.checks.builtin.text_matching`

<Property name="pattern" type="str | MISSING" defaultValue="MISSING">
  Regular expression pattern.
</Property>
<Property name="pattern_key" type="JSONPathStr | MISSING" defaultValue="MISSING">JSONPath to extract the regex pattern from the trace. Provide exactly one of `pattern` or `pattern_key`.</Property>
<Property name="text" type="str | MISSING" defaultValue="MISSING">Static text to match against. Left at `MISSING`, the check reads `target_key`.</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract text to match against.
</Property>
<Property name="match_timeout_seconds" type="float" defaultValue="2.0">
  Upper bound on how long regex matching may take before the check errors. Must be greater than 0.
</Property>

The agent's reply must never contain a full card number. Wrap the matcher in [`Not`](#not) so a match is a failure:

```python
from giskard.checks import Not, RegexMatching

check = Not(
    check=RegexMatching(
        pattern=r"\b(?:\d[ -]?){13,16}\b",
        target_key="trace.last.outputs.answer",
    )
)
```

Use `RegexMatching` for shapes: card numbers, IBANs, payment references, dates. For a fixed phrase, [`StringMatching`](#stringmatching) is clearer and cannot be broken by an escaping mistake.

</ResourceSection>

## Comparison Checks

Validate numeric and comparable values against expected thresholds.

**Module:** `giskard.checks.builtin.comparison`

The six comparison checks take the same four fields, listed in full under each one. Provide exactly one of `expected_value` or `expected_value_key`; leaving both at `MISSING` makes the check error at run time because it has nothing to compare against.

`match` decides what happens when `target_key` resolves to several values, which any wildcard or slice path does — see [Multi-match paths](/oss/checks/explanation/jsonpath-in-checks#multi-match-paths).

**Raises:** `ValidationError` at construction when `expected_value_key` or `target_key` does not start with `trace.`. `CheckResult.error` (not a failure) at run time when a path resolves to nothing, or when the two values are not comparable — for example `LessThan` against a string.

### `Equals`

<ResourceSection description="Check that the extracted value equals an expected value. Deterministic and free.">

<TypeTable name="Equals">
  <Property name="expected_value" type="Any | MISSING" defaultValue="MISSING">
    Static expected value.
  </Property>
  <Property name="expected_value_key" type="JSONPathStr | MISSING" defaultValue="MISSING">
    JSONPath to the expected value in the trace.
  </Property>
  <Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
    JSONPath to the value being checked.
  </Property>
  <Property name="normalization_form" type='Literal["NFC", "NFD", "NFKC", "NFKD"] | None' defaultValue='"NFKC"'>
    Unicode normalization applied to both sides before comparing.
  </Property>
  <Property name="match" type='Literal["any", "all", "none"] | MISSING' defaultValue="MISSING">
    How to apply the comparison when the resolved value is a list, set, or tuple.
    Omit it to compare the resolved value directly. `"any"` passes when at least
    one item matches, `"all"` when every item does, `"none"` when no item does.
  </Property>
</TypeTable>

The agent classifies each request before answering it. Assert on the classification field, not on the sentence around it:

```python
from giskard.checks import Equals

count_is_42 = Equals(expected_value=42, target_key="trace.last.outputs.count")
status_is_success = Equals(
    expected_value="success", target_key="trace.last.outputs.status"
)
```

Use `Equals` on values your agent produces as data: labels, enums, identifiers, numbers. On free text it fails on any rewording, so compare meaning with [`SemanticSimilarity`](#semanticsimilarity) instead.

`expected_value_key` compares two points in the same trace. Ask the same question twice and require the same classification:

```python
intent_is_stable = Equals(
    expected_value_key="trace.interactions[0].outputs.intent",
    target_key="trace.last.outputs.intent",
)
```

</ResourceSection>

## JSON Validation

### `JsonValid`

<ResourceSection description="Check that a trace value is valid JSON. Accepts a JSON string or an already-parsed JSON-compatible value (dict, list, string, number, boolean, or None). Optionally validates against a JSON Schema.">

**Module:** `giskard.checks.builtin.json_valid`

<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath expression to extract the value to validate.
</Property>
<Property name="parse" type="bool" defaultValue="True">
  With `True`, the extracted value must be a serialized JSON **string**, parsed
  with `json.loads` before validation; a non-string value returns
  `CheckResult.error`. Set it to `False` when the target already returns a
  parsed value such as a dict or a list.
</Property>
<Property name="expected_schema" type="dict[str, Any] | None" defaultValue="None">
  Optional JSON Schema for the parsed value. Serialized as `schema` in JSON.
</Property>

For an already-parsed value, set `parse=False`:

{/* pyright-skip: Pydantic types the constructor alias schema; the Python field is expected_schema. */}
```python
from giskard.checks import JsonValid

check = JsonValid(target_key="trace.last.outputs")

check = JsonValid(
    target_key="trace.last.outputs",
    parse=False,
    expected_schema={
        "type": "object",
        "required": ["answer", "category"],
        "properties": {
            "answer": {"type": "string"},
            "category": {"type": "string"},
        },
    },
)
```

Keep the default `parse=True` for JSON returned as text.

**Raises:** `CheckResult.error` when `parse=True` and the resolved value is not a string.

Use `JsonValid` when the agent is asked to produce machine-readable output and a downstream system will parse it. It says nothing about whether the content is correct, so pair it with a judge.

</ResourceSection>

## Policy Checks

### `RegoPolicy`

<ResourceSection description="Evaluate an inline Rego policy against trace data using Regorus, an OPA-compatible Rego engine. Extracts the value passed as input from the trace via JSONPath, merges optional static data, and evaluates a boolean rule.">

**Module:** `giskard.checks.builtin.rego_policy`

:::note[Optional dependency]
Requires the `regorus` extra: `pip install --pre 'giskard[regorus]'` (installs the [Regorus](https://github.com/microsoft/regorus) `celine-regorus` wheel; import as `regorus`).
:::

<Property name="policy" type="str" required>
  Inline Rego source loaded into the engine.
</Property>
<Property name="rule" type="str" required>
  Fully qualified boolean rule path (e.g. `data.giskard.allow`). Must evaluate to a boolean, be undefined (fail), or error on other types.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath into the trace for the JSON value exposed to the policy as `input`.
</Property>
<Property name="data" type="dict[str, Any]" defaultValue="{}">
  Static `data` document merged into the policy engine via `engine.add_data` (separate from `input`).
</Property>

Only a reply to an authenticated customer may carry an account balance:

```python
from giskard.checks import RegoPolicy

check = RegoPolicy(
    policy="""
package giskard

default allow = false

allow if {
    not input.contains_balance
}

allow if {
    input.contains_balance
    input.authenticated
}
""",
    rule="data.giskard.allow",
    target_key="trace.last.metadata",
)
```

**Raises:** `ValidationError` at construction when the `regorus` extra is not installed. `CheckResult.error` at run time when the rule evaluates to a non-boolean; an undefined rule is a failure, not an error.

Use `RegoPolicy` when the rule already exists as policy elsewhere in your stack and you want one source of truth. For a one-off condition, [`FnCheck`](#fncheck) is less machinery.

</ResourceSection>

## Check Composition

Combine built-in or custom checks with logical operators. All composition checks are in `giskard.checks.builtin.composition`.

### `AllOf`

<ResourceSection description="Passes only when all inner checks pass. Short-circuits on the first failure or error; a skipped inner check does not stop evaluation.">

<Property name="checks" type="list[Check]" required>
  Ordered list of checks to evaluate. All must pass.
</Property>

`AllOf` runs its checks in order and returns the first result that is neither a pass nor a skip, so a FAIL or an ERROR stops it. A skipped inner check is not a failure and evaluation continues past it. If **every** inner check skipped, the result is `CheckResult.skip("All checks were skipped.")` — a skip, not a pass, so an `AllOf` whose members all opted out cannot be mistaken for a green verdict.

A balance answer counts as good only if the customer was authenticated and the figure was sourced:

```python
from giskard.checks import AllOf, Equals, GreaterThanEquals

check = AllOf(
    checks=[
        Equals(
            expected_value=True, target_key="trace.last.outputs.authenticated"
        ),
        GreaterThanEquals(
            expected_value=1, target_key="trace.last.metadata.citation_count"
        ),
    ]
)
```

Adding the same checks separately with `.check()` gives you a verdict per check, which is easier to debug. Use `AllOf` when the conjunction is what you want to report, or when you need to nest it inside `AnyOf` or `Not`.

</ResourceSection>

### `AnyOf`

<ResourceSection description="Passes when at least one inner check passes. Short-circuits on the first pass or error.">

<Property name="checks" type="list[Check]" required>
  Ordered list of checks to evaluate. At least one must pass.
</Property>

`AnyOf` returns the first result that passes **or errors** — an erroring inner check is surfaced immediately rather than being treated as one more failed alternative, so a broken check cannot hide behind a later passing one. If every inner check skipped, the result is `CheckResult.skip("No checks passed and all were skipped.")`.

Faced with a disputed card payment, the agent may either open the dispute or ask for the details it still needs. Both are acceptable; closing the case unprompted is not:

```python
from giskard.checks import AnyOf, Equals

check = AnyOf(
    checks=[
        Equals(
            expected_value="opened", target_key="trace.last.outputs.dispute_status"
        ),
        Equals(
            expected_value="information_requested",
            target_key="trace.last.outputs.dispute_status",
        ),
    ]
)
```

Put cheap known cases first, then use a judge as a fallback when needed. For "one item in a list matches", use the comparison checks' `match="any"` instead.

</ResourceSection>

### `Not`

<ResourceSection description="Inverts the result of an inner check. Pass becomes fail and fail becomes pass. Error and skip results pass through unchanged.">

<Property name="check" type="Check" required>
  The inner check whose result will be inverted.
</Property>

Use `Not` to reject matching output:

```python
from giskard.checks import Not, StringMatching

check = Not(
    check=StringMatching(
        keyword="unsupported claim",
        target_key="trace.last.outputs.answer",
        case_sensitive=False,
    )
)
```

`Not` is how you express "must never". An inner check that errors or skips passes its result through unchanged, so a broken inner check does not silently turn into a pass.

</ResourceSection>

## LLM judges

Validation checks powered by Large Language Models for semantic understanding. Each verdict costs one LLM call. An LLM judge is another model reading the transcript and returning a verdict. It can be wrong in both directions: read failures before you act, and do not treat a passing suite as proof the agent is safe.

### `BaseLLMCheck`

<ResourceSection description="Abstract base class for creating custom LLM-powered checks. Handles LLM interaction, prompt rendering, and result parsing — subclasses only need to define the evaluation prompt.">

**Module:** `giskard.checks.judges.base`

<TypeTable name="BaseLLMCheck">
  <Property name="generator" type="BaseGenerator | None" defaultValue="None">
    LLM generator for evaluation. Falls back to the global default if not
    provided.
  </Property>
  <Property name="name" type="str | None" defaultValue="None">
    Optional check name.
  </Property>
  <Property name="description" type="str | None" defaultValue="None">
    Optional description.
  </Property>
</TypeTable>

<MethodCard
  name=".get_prompt()"
  returnType="str | Message | MessageTemplate | TemplateReference"
>
  Returns the prompt to send to the LLM. Subclasses must implement this method.
</MethodCard>

<MethodCard name="async .get_inputs()" returnType="dict[str, Any]">
  Provides template variables for prompt rendering. Override to customize available variables. Default: `{"trace": trace}`.

  <Property name="trace" type="Trace" required>The trace containing interaction history.</Property>
</MethodCard>

<MethodCard name="async .run()" returnType="CheckResult">
  Execute the LLM-based check (inherited, usually doesn't need overriding).

  <Property name="trace" type="Trace" required>The trace to evaluate.</Property>
</MethodCard>

```python
from giskard.checks.judges.base import BaseLLMCheck


@BaseLLMCheck.register("rule_check")
class RuleCheck(BaseLLMCheck):
    forbidden_text: str

    def get_prompt(self):
        return f"""
        The reply must not include: {self.forbidden_text}

        Customer: {{{{ trace.last.inputs }}}}
        Assistant: {{{{ trace.last.outputs }}}}

        Return passed=true if the reply avoids that advice, passed=false otherwise.
        """


check = RuleCheck(forbidden_text="unsupported claim")
```

Subclass `BaseLLMCheck` when the same judgement recurs across suites and you want it named, registered, and serializable. For a one-off criterion, [`LLMJudge`](#llmjudge) takes the prompt directly.

</ResourceSection>

### `LLMCheckResult`

**Module:** `giskard.checks.judges.base`

Default result model for LLM-based checks. This is the structured output format expected from the LLM.

<TypeTable name="LLMCheckResult">
  <Property name="passed" type="bool">
    Whether the check passed.
  </Property>
  <Property name="reason" type="str" required>
    Explanation for the verdict. Required and non-blank: it is stripped, then
    validated with `min_length=1`. A judge that returns `None` or an empty
    string raises a `ValidationError` instead of producing a result.
  </Property>
</TypeTable>

### `Groundedness`

<ResourceSection description="Validates that answers are grounded in provided context documents. Essential for RAG systems to ensure responses don't hallucinate information.">

**Module:** `giskard.checks.judges.groundedness`

<Property name="answer" type="str | MISSING" defaultValue="MISSING">
  The answer text to evaluate (static). Left at `MISSING`, the check reads `target_key`.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract answer from trace.
</Property>
<Property name="context" type="str | list[str] | MISSING" defaultValue="MISSING">
  Context document(s) that should support the answer (static). Left at `MISSING`, the check reads `context_key`.
</Property>
<Property
  name="context_key"
  type="str"
  defaultValue='"trace.last.metadata.context"'
>
  JSONPath to extract context from trace.
</Property>
<Property name="generator" type="BaseGenerator | None" defaultValue="None">
  LLM generator for evaluation.
</Property>

Use `Groundedness` to compare an answer with retrieved documents:

```python
from giskard.checks import Groundedness

check = Groundedness(
    target_key="trace.last.outputs.answer",
    context_key="trace.last.metadata.retrieved_docs",
)
```

You can also pass static values:

```python
check = Groundedness(
    answer="The archive holds 20 documents.",
    context=[
        "The archive holds 10 documents.",
    ],
)
```

**Raises:** `CheckResult.error` when neither the static field nor its `*_key` path yields a value, and when the provider call fails.

Use `Groundedness` when every claim must be supported by the context. Use [`Contradiction`](#contradiction) when you only need to catch conflicts.

</ResourceSection>

### `AnswerRelevance`

<ResourceSection description="LLM-based check that evaluates whether the model's answer is relevant to the question. Uses conversation history for context but scores only the current turn.">

**Module:** `giskard.checks.judges.answer_relevance`

<Property name="question" type="str | MISSING" defaultValue="MISSING">
  Question to evaluate against. Left at `MISSING`, the check reads `question_key`.
</Property>
<Property name="question_key" type="str" defaultValue='"trace.last.inputs"'>
  JSONPath to extract the question from the trace.
</Property>
<Property name="answer" type="str | MISSING" defaultValue="MISSING">
  Answer to evaluate. Left at `MISSING`, the check reads `target_key`.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract the answer from the trace.
</Property>
<Property name="context" type="str | MISSING" defaultValue="MISSING">
  Optional domain context describing the chatbot's purpose (not extracted from the trace).
</Property>
<Property name="include_history" type="bool" defaultValue="True">
  Whether earlier interactions are shown to the judge as context. Turn it off to
  score the last turn in isolation.
</Property>
<Property name="generator" type="BaseGenerator | None" defaultValue="None">
  LLM generator for evaluation (falls back to default).
</Property>

Use this check when an answer should address the current question:

```python
from giskard.checks import AnswerRelevance, Scenario

scenario = (
    Scenario(name="answer_relevance")
    .interact(
        inputs="Where is item 42?",
        outputs="In the archive.",
    )
    .interact(
        inputs="Who created it?",
        outputs="The archive is open at 9am.",
    )
    .check(
        AnswerRelevance(
            context="An assistant for a document archive."
        )
    )
)
```

`AnswerRelevance` evaluates relevance, not factual accuracy. Use [`Groundedness`](#groundedness) to evaluate support from context.

</ResourceSection>

### `Toxicity`

<ResourceSection description="LLM-based check that detects toxic, harmful, or offensive content across configurable categories.">

**Module:** `giskard.checks.judges.toxicity`

<Property name="output" type="str | MISSING" defaultValue="MISSING">
  Text to evaluate. Left at `MISSING`, the check reads `target_key`.
</Property>
<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to extract the output from the trace.
</Property>
<Property name="categories" type="list[ToxicityCategory]" defaultValue='["hate_speech", "harassment", "threats", "self_harm", "sexual_content", "violence"]'>
  Toxicity categories to evaluate. Restrict the list to focus the judge.
  `ToxicityCategory` is a `Literal` over exactly those six values; any other
  string raises a `ValidationError` when you construct the check.
</Property>
<Property name="generator" type="BaseGenerator | None" defaultValue="None">
  LLM generator for evaluation (falls back to default).
</Property>

Customers whose card has just been declined are sometimes abusive. The check is on the reply, not the message:

```python
from giskard.checks import Toxicity, Scenario

scenario = (
    Scenario(name="stays_civil")
    .interact(
        inputs="This answer is useless.",
        outputs="I can help clarify the answer.",
    )
    .check(Toxicity(categories=["harassment", "threats"]))
)
```

Narrowing `categories` focuses the judge on what you actually care about and cuts false positives. Use `Toxicity` for the reply's tone and content; use [`Conformity`](#conformity) when the rule you want to enforce is specific to your product.

</ResourceSection>

### `Conformity`

<ResourceSection description="Validates that a trace conforms to a given rule. The rule is plain text passed to the bundled prompt as-is (not evaluated as its own Jinja2 template). The full trace is supplied to the model for judgment.">

**Module:** `giskard.checks.judges.conformity`

<Property name="rule" type="str" required>
  The rule statement to evaluate against the trace (literal text).
</Property>
<Property name="generator" type="BaseGenerator | None" defaultValue="None">
  LLM generator for evaluation (falls back to default).
</Property>

Write the rule as one sentence a colleague could apply by hand:

```python
from giskard.checks import Conformity

check = Conformity(
    rule=(
        "The reply must not recommend a specific investment product "
        "and must direct regulated questions to a qualified adviser."
    )
)
```

The same check states the disclosure rule the agent has to hold to:

```python
check = Conformity(
    rule="The reply must not reveal details of any account other than the one the customer is authenticated for."
)
```

Use `Conformity` for a policy you can state as a rule. If the rule keeps growing clauses, split it into several `Conformity` checks so a failure tells you which clause broke, or move to [`LLMJudge`](#llmjudge) for a prompt with its own structure.

</ResourceSection>

### `LLMJudge`

<ResourceSection description="General-purpose LLM-based validation with custom prompts. The most flexible LLM check — use it when Groundedness or Conformity do not fit.">

**Module:** `giskard.checks.judges.judge`

<Property name="prompt" type="str | None">
  Inline prompt content with Jinja2 templating support.
</Property>
<Property name="prompt_path" type="str | None">
  Path to a template file (e.g. `"checks::my_template.j2"`).
</Property>
<Property name="generator" type="BaseGenerator | None" defaultValue="None">
  LLM generator for evaluation.
</Property>

Exactly one of `prompt` or `prompt_path` must be provided.

**Template variables available in prompts:**

| Variable              | Description                               |
| --------------------- | ----------------------------------------- |
| `trace`               | Full trace object with all interactions   |
| `trace.interactions`  | List of all interactions in order         |
| `trace.last`          | Most recent interaction                   |
| `trace.last.inputs`   | Inputs from the most recent interaction   |
| `trace.last.outputs`  | Outputs from the most recent interaction  |
| `trace.last.metadata` | Metadata from the most recent interaction |

Judge one turn against criteria no built-in check expresses. Spell out what a failure looks like, or the judge invents its own standard:

```python
from giskard.checks import LLMJudge

check = LLMJudge(
    prompt="""
    Customer: {{ trace.last.inputs }}
    Assistant: {{ trace.last.outputs }}

    The reply passes only if it answers the customer's question and states the
    relevant information needed to answer it.
    """,
)
```

Across turns, iterate the trace to check for contradictions:

```python
check = LLMJudge(
    prompt="""
    {% for interaction in trace.interactions %}
    Customer: {{ interaction.inputs }}
    Assistant: {{ interaction.outputs }}
    {% endfor %}

    Return passed=false if the assistant contradicts an earlier answer.
    """,
)
```

**Raises:** `ValidationError` at construction unless exactly one of `prompt` or `prompt_path` is set. `CheckResult.error` at run time when the provider call fails or the model returns a blank `reason`.

Reach for `LLMJudge` last. If the criterion fits [`Conformity`](#conformity), [`Groundedness`](#groundedness), or a rule-based check, those are cheaper, and the rule-based ones do not vary between runs.

</ResourceSection>

## Embedding-based checks

No judge, but not free either: these call an embeddings API, so they need a configured provider and a key.

### `SemanticSimilarity`

<ResourceSection description="Validate semantic similarity between outputs and expected content using embeddings.">

**Module:** `giskard.checks.builtin.semantic_similarity`

<Property name="reference_text" type="str | MISSING" defaultValue="MISSING">
  Reference text to compare against (static). Left at `MISSING`, the check reads `reference_text_key`.
</Property>
<Property
  name="reference_text_key"
  type="str"
  defaultValue='"trace.last.metadata.reference_text"'
>
  JSONPath to extract reference text from trace.
</Property>
<Property
  name="target_key"
  type="str"
  defaultValue='"trace.last.outputs"'
>
  JSONPath to extract actual value from trace.
</Property>
<Property name="threshold" type="float" defaultValue="0.95">
  Similarity threshold (0.0 to 1.0).
</Property>
<Property name="embedding_model" type="BaseEmbeddingModel | None" defaultValue="None">Embedding model used to compute similarity scores. `None` falls back to the global default.</Property>

The agent rewords the dispute procedure every run, but the procedure itself must not drift:

```python
from giskard.checks import SemanticSimilarity

check = SemanticSimilarity(
    reference_text="Card disputes are investigated within 15 working days, and any provisional refund is returned if the claim is rejected.",
    target_key="trace.last.outputs.answer",
    threshold=0.8,
)
```

Use it when phrasing varies but meaning must not. The default `threshold` of 0.95 accepts near-identical text only; loosen it and check the failures, because embeddings score "within 15 working days" and "within 15 months" as very close. When the requirement is a judgement rather than a resemblance, use [`Conformity`](#conformity).

</ResourceSection>

## Text metrics

Deterministic, local, and free — no provider involved.

### `Readability`

<ResourceSection description="Compute a readability score for a trace value with textstat and validate it against optional thresholds. Deterministic.">

**Module:** `giskard.checks.builtin.nlp_metrics`

:::note[Optional dependency]
Requires the `textstat` dependency, which ships with the `all-checks` extra: `pip install --pre 'giskard[all-checks]'`.
:::

<Property name="target_key" type="str" defaultValue='"trace.last.outputs"'>
  JSONPath to the text to score.
</Property>
<Property name="metric" type='ReadabilityMetric' defaultValue='"flesch_reading_ease"'>
  One of `flesch_reading_ease`, `flesch_kincaid_grade`, `gunning_fog`,
  `automated_readability_index`, `coleman_liau_index`,
  `dale_chall_readability_score`.
</Property>
<Property name="min_score" type="float | None" defaultValue="None">
  Minimum acceptable score. Use with higher-is-easier metrics such as `flesch_reading_ease`.
</Property>
<Property name="max_score" type="float | None" defaultValue="None">
  Maximum acceptable score. Use with grade-level metrics, where lower is easier.
</Property>

The agent writes for retail customers, not for the compliance team, so its answers should read as plain English:

```python
from giskard.checks import Readability

check = Readability(
    target_key="trace.last.outputs.answer",
    metric="flesch_reading_ease",
    min_score=60,
)
```

Readability scores measure sentence and word length, not clarity. A reply can score well and still be wrong, so pair it with a check on the content.

**Raises:** `ValidationError` at construction when `min_score > max_score`, and when the optional `textstat` dependency is not installed.

</ResourceSection>

## Common patterns

### Combining multiple checks

Chain checks on a scenario, or wrap them with `AllOf`, `AnyOf`, and `Not` (see [Check Composition](#check-composition)).

Order matters for cost. The free checks below run first, and the judge only sees traces that already have a citation:

```python
from giskard.checks import Conformity, Equals, FnCheck, Scenario


def bank_support_agent(inputs: str) -> dict:
    return {
        "answer": "Your current account ending 4417 is 1,284.50 EUR in credit.",
        "intent": "balance_enquiry",
        "authenticated": True,
        "citations": ["fee-schedule/current-account"],
    }


scenario = (
    Scenario("balance_enquiry")
    .interact(
        inputs="How much is in my current account?",
        outputs=lambda inputs: bank_support_agent(inputs),
    )
    .check(
        Equals(
            expected_value=True, target_key="trace.last.outputs.authenticated"
        )
    )
    .check(
        FnCheck(
            fn=lambda trace: trace.last is not None
            and len(trace.last.outputs["citations"]) > 0,
            name="cites_fee_schedule",
        )
    )
    .check(
        Conformity(
            rule="The reply must not disclose a balance unless the customer is authenticated."
        )
    )
)
```

The last check calls an LLM provider, so this scenario sends the trace off your machine.

### Reusing generators

Set the judge model once instead of passing it to every LLM check:

```python
from giskard.agents.generators import Generator
from giskard.checks import Conformity, Groundedness, set_default_generator

set_default_generator(
    Generator(model="openai/gpt-5").with_params(temperature=0.1)
)

check = Groundedness(target_key="trace.last.outputs.answer")
check = Conformity(
    rule="The reply must include a citation."
)
```

A low temperature makes verdicts steadier across runs, but does not make them deterministic. Two runs of the same suite can disagree.

### Creating custom checks

Subclass `Check`, implement `async def run(self, trace) -> CheckResult`, and register the subclass with `@Check.register("kind")` so it survives serialization:

```python
from giskard.checks import Check, CheckResult, Trace


@Check.register("quotes_published_fee")
class QuotesPublishedFee(Check):
    published_fees: dict[str, float]

    async def run(self, trace: Trace) -> CheckResult:
        if trace.last is None:
            return CheckResult.skip(message="No interaction to check")
        return CheckResult.success(message="Quoted a published fee")
```

Fields are ordinary Pydantic fields, and `extra="forbid"` applies to your subclass too. For the full walkthrough — registration, metrics, composing several checks, and when to prefer [`FnCheck`](#fncheck) — see [Custom checks](/oss/checks/how-to/custom-checks).
